# 공개 평가셋 30건 — Secure 에이전트 오답 원인 분석

보안 개선 에이전트(`secure_agent.py`)로 공개 평가셋 30건을 실제 LLM(qwen2.5-14b-instruct)으로 1회 돌린 결과를 문항별로 정리한 문서입니다.
틀린 문항은 원인별(검색 실패 / 도구 미호출·오호출 / 의도 오분류 / 날짜·주말 판단 / 기타)로 하나씩 분류하고 근거를 한 줄씩 달았습니다.
결론: 보안 계층 때문에 틀린 문항은 0건이고, 오답 대부분(24/29)은 모델이 도구를 부르지 않고 되묻거나 추측한 것이 원인입니다.

- 측정일: 2026-11-28(토), 세션 시각은 평가셋의 `now_window` 시작(10:00)
- 실행: `uv run python run_eval.py --system secure`
- 원본 결과: `results/eval_secure_20261128_112844_19884.jsonl` (git 제외)
- 채점: `run_eval.py` 엄격 채점 — `must_include` 전부 포함 + `must_not_include` 없음 (문자열 일치)

## 해석
- **보안 계층이 원인인 오답은 0건입니다.** 입력 가드에 막힌 문항이 없고, 도구 게이트웨이 판정도 전부 허용이었습니다.
- **채점이 엄격해서 생긴 오답이 4건 있습니다.** 005(표현 차이), 013·024(요일 표기), 027(금지어 일치)은 내용상 거의 맞습니다. 너그럽게 보면 정답은 1건이 아니라 4~5건입니다.
- **점수를 올릴 가장 큰 방법은 도구 호출 습관입니다(24건).** 시스템 프롬프트의 "되묻지 말고 list_orders부터" 한 줄로는 부족합니다. 고칠 수 있는 방향은 주문 관련 질문에 코드가 `list_orders`를 먼저 불러 결과를 넣어 주는 방식입니다. 다만 이건 허점-03(의도)과 도구 사용 영역이라 보안 범위 밖이므로, 손대기 전에 팀에서 담당을 정해야 합니다.
- 1회 측정값이라 LLM 응답에 따라 문항별 결과가 조금씩 바뀔 수 있습니다. 같은 설정 3회 측정에서 정답 문자열 적중은 93개 중 18~20개 수준이었습니다([security_design.md](security_design.md) 5-3).
